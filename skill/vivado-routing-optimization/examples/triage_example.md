# 合成数据示例：候选中途停止

本示例所有 run ID、参数、耗时、网络数量和时序值均为虚构的教学数据，不来自本工程或实际 Vivado 运行。它只演示如何避免把中途日志误判为通过。

## 示例输入

目标：比较一项 routing directive 的候选是否缩短完整实现时间。

| 字段 | 基线（合成） | 候选（合成） |
| --- | --- | --- |
| 器件 / 时钟 / 工具 | `example_part` / 10 ns / `Vivado example` | 相同 |
| RTL 与 XDC 身份 | `rtl-demo-a` / `xdc-demo-a` | 相同 |
| 唯一改动 | 无 | `directive-demo-b` |
| run 状态 | `COMPLETED` | `STOPPED_BY_USER` |
| elapsed | 42 min | 36 min 后停止 |
| route status | 1,000/1,000 nets | 820/1,000 nets |
| 最终 WNS/TNS | -0.02/-0.02 ns | 未生成 |

## 示例判断

基线完整结束但没有达到示例 setup 门槛。候选停止时只完成了 820/1,000 条网络，且没有最终时序报告。36 min 是截至停止时的时间，不是候选完整运行时间，不能据此声称提速，也不能说候选 route 失败。当前只能报告“候选用户停止，尚无最终结果”。

下一步若获授权，应在独立目录确认候选命令和资源限制，重新完成同范围实现并收集 route、timing、coverage 和 DRC 报告。若不再运行，则保留停止状态和缺失证据，不推断最终质量。
