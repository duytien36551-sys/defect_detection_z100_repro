# Vivado 布线优化

工程包上下文（2026-11-03）：额外硬件源码构建按用户要求在布线阶段停止，未产生新的最终route、bit或XSA验收结果；下文资源及时序数值仍是明确标注的历史摘要。

## 适用范围

用于已有 Vivado 工程的实现时间、拥塞、时序、检查点复用问题。目标是提出并评价一项有证据的优化实验，同时保留设计身份和验收要求。它不用于推断板端吞吐，也不自动启动、停止或恢复构建。

## 使用方法

先阅读 [技能入口](skill.md) 和 [操作工作流](references/workflow.md)。把以下提示词与工程目录和期望目标一起提供：

> 请按 Vivado 布线优化工作流先只读盘点这个工程。核对活跃运行状态、源码与约束身份、工具/器件/时钟、阶段耗时、资源、拥塞和时序报告。给出证据、未知项和一项最小可比较实验；不要启动、停止或重启构建。若需要构建，请先列出命令、资源预算、停止条件和验收门槛。

执行者应先从当前工程自动查找运行记录、Vivado 日志、阶段报告、约束、DCP、源清单和机器资源信息。用户不必先手动整理文件；只有关键证据无法定位或授权边界不清时，才列出具体缺项。启动新实验须有明确授权，并避免覆盖现有运行目录或争抢资源。

## 输入与输出

关键输入包括：运行 ID 和退出码；Vivado 版本、器件、顶层和时钟；源码、XDC、DCP 的身份和阶段；运行配置、线程数、机器负载；place、physopt、route 阶段时间；拥塞、资源、setup/hold/pulse-width、时序覆盖、route status 和 DRC 报告。比较候选时，器件、时钟、约束、工具版本和设计输入应相同，或明确标出差异及不可比原因。

结果应区分实测、推导和未知，给出基线/候选配置表、阶段和最终门槛、失败或停止状态、证据位置，以及下一项实验及其停止条件。使用 [报告模板](assets/validation_report_template.md)；[合成示例](examples/triage_example.md)只演示报告方法，不是工程测量。

## 验收边界

只有最终完整平台报告才能支持完整平台 route/timing 结论。route 完成、无未布线网络、时序覆盖完整、setup/hold/pulse-width 通过、关键 DRC 门槛满足应分别记录。Warning 分组数量仍需报告，不能把零 Error/Critical Warning 写成零 DRC Warning。OOC、阶段检查点、bit/XSA 导出、实板功能及 FPS 是不同范围的结果。

现有包中的 [最终硬件历史摘要](../../report/final_hardware/synthesis_implementation_summary.md)记录了一份 Vivado 2026.1、`xc7z100ffg900-2` 历史 post-route 结果：WNS/TNS 为 `0.005/0 ns`，WHS/THS 为 `0.045/0 ns`，238,792 条网络全部布通，Error/Critical Warning DRC 为 0，Warning DRC 分组为 1,447。该记录不代表新的源码重建、重新布线或板级验证；原始工具报告和构建日志按工程包范围未包含。此技能自身没有脚本或验证报告，不计入原五项技能共62项历史工具测试。

## 限制

一次运行不证明普遍提速；中间 WNS、迭代数、重叠数不是最终通过或 ETA。CPU 时间和墙钟时间不能混用；不同阶段或不同设计身份的指标不能直接比较。RTL 修改可能影响功能、周期行为和端到端性能，应按工程要求另行验证。
