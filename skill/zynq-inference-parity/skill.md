# 分层一致性与量化验证

固定模型、输入、预处理、dtype、形状、布局与尺度，查找最早不一致位置。

先读取详细工作流（文件：references/workflow.md），按其步骤执行；这是本技能的主要操作说明。

## 材料发现与授权

优先从当前工程、配置、构建产物、日志及可访问聊天记录查找材料，核对身份与完整性。没有聊天访问能力时继续从工程证据取证，不要求用户重复搜集可访问资料。只有查找后仍有关键缺项、歧义或需要实体操作及必要授权时才询问。未生成的实测证据标为缺失，参考结果和计划不替代实测。

下载、初始化、板卡复位、持久存储写入和训练进程控制须由当前任务授权；加载技能本身不提供授权。可继续独立的只读检查，不扩大任务范围。

## 历史证据与能力边界

需要案例时读取经验来源（文件：references/lessons.md）。材料为历史记录的脱敏示例与核验说明，记录了失败、修正和限制，不代表当前运行状态。旧板地址、时钟、类别和质量门槛不可直接移植。历史聊天中的模型分工不构成当前调用要求。

1.0.0历史工作流验证：两个本地材料案例已完成独立行为执行与主线程证据复核，跨项目验证限于所记录的静态材料审查。结果与范围见验证摘要（文件：validation/review_summary.json）。没有通用PYNQ跨板结论。仅在任务需要时读取案例证据。

## 交付

分别输出实现一致性表、首个差异、量化精度差（百分点）及缺项。

需要完整报告时使用报告模板（文件：assets/validation_report_template.md），只填写本次任务相关部分，其余标记未评估。

不同模型或张量契约不能直接比较；浮点字节差异须按声明的数值误差规则另行判断。

原始二进制比较可调用只读比对脚本（文件：scripts/compare_binary.py）。使用脚本的绝对路径，不依赖当前工作目录；先核对模型、输入和张量契约。

按 dtype 与容差比较原始张量时，读取自动化数值比对说明（文件：references/automation.md）并运行 `scripts/compare_tensor.py`；它只验证数值契约，不判定模型质量。

运行示例和明确限制见本技能说明（文件：readme.md）。

## 组合任务与工具边界

先判断本次问题属于身份、输出差异、性能、DMA现场或训练质量；跨领域问题按证据依赖依次检查。仅在需要时加载其他已安装技能；缺少其他技能时按本工作流完成可做部分。自动化工具只验证声明的输入契约与可计算事实，材料发现和工程结论仍须核对原始证据。新版工具验证见自动化说明（文件：references/automation.md），历史案例不自动算作新工具的验收。

## 真实材料适配

当前工程材料若符合自动化说明（文件：references/automation.md）列出的格式，优先使用对应材料适配器，保存输入SHA-256、字段映射、命令和原始输出。未知格式先核对语义再转换；不能用默认值补出成功，也不能将历史记录复算称为新实板或训练结果。

## 二：分层一致性与量化

适用：部署结果异常、后端迁移、量化精度下降、硬件算术变更。

执行所需材料（由 Codex 优先自动查找）：冻结模型/输入、相同预处理、张量 dtype/形状/布局、每个后端的原始输出。

流程：
1. 官方浮点与导出浮点比较，先排除导出、预处理和解码差异。
2. 整数参考与 scalar C 比较，再与 mock/RTL 比较，最后比较实际板端。
3. 使用同一输入和同一包。发现差异时定位首个分歧层或索引，保存双方输入与参数。
4. 分别检查累计位宽、舍入、饱和、缩放、DFL/检测头等算术契约；不预设根因。
5. 完整验证集以相同部署预处理比较浮点与量化精度，损失按百分点报告。测试集不用于选方案。
6. 算术一致、量化质量、业务效果分别判定。

提示词：

> 把这些结果按浮点导出、整数语义、C/RTL实现、实板执行分层核对。找最早不一致位置；若检测头一致但AP下降，继续检查量化误差，不将执行一致判为质量通过。列出各结论覆盖的图片数和缺失证据。

工具：

```text
python <本技能绝对路径>/scripts/compare_binary.py <参考文件路径> <待比较文件路径> --label raw-head
```

脚本报告字节长度、SHA-256、首个差异偏移、共享范围内不同字节数、尾部长差和总差异位置数。它不解析 dtype、字节序、布局或检测框语义；张量契约由使用者先核对。输入读取期间必须保持文件不变。

输出：层级结果表、差异报告、量化精度差及缺项。失效条件：输入/布局/尺度不一致，或者参考自身未经验证；此时二进制差异只能作为现象。

历史经验和本次核验范围见经验说明（文件：lessons.md）与验证摘要（文件：../validation/review_summary.json）。


## 本次复核补充

先确认逻辑输出长度、dtype、字节序和布局，再解释捕获文件。存储对齐填充不属于张量；只在可信契约声明的范围比对，并同时记录完整文件与逻辑范围的哈希。只有板端字节及报告中expected哈希时，可重算板端哈希但不能声称新完成了两端逐字节比较。参考在采集后修正的历史必须披露。
