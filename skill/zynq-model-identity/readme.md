## 适用范围

用于换板、换权重、输入尺寸变化和版本冲突，输出目标/候选/实际运行的身份表，避免把构建通过误当成部署完成。 执行材料由Codex先从当前工程、配置、日志和可访问记录自动查找；找不到的关键证据再明确列出。入口见skill.md（文件：skill.md），操作方法见详细工作流（文件：references/workflow.md）。

## 使用方法

> 使用 $zynq-model-identity，自动查找当前工程材料，按工作流执行，给出结论、证据、缺项和下一项最小检查。

也可以按工作流人工操作。技能本身不授权复位、下载到板、写入持久存储或控制训练。

## 失效条件

模型或协议HELLO一致，只能确认这些字段；若运行端不报告ELF/bitstream/XSA身份，不能由相同模型哈希推断整套构建物已在该次执行。核对时间线，区分后构建清单与先前运行记录。对每个哈希标注“本次从文件重算”或“原报告声明”；文件未随材料提供时不冒称重算。

## 来源与限制

同一历史模型的构建清单和运行记录时间不同，且HELLO没有ELF/XSA字段。模型匹配不能证明所有硬件产物匹配。缺失运行记录的例子是明确标注的构造缺项测试。

真实协作问题、观察、纠错及结果的选定链见协作来源（文件：evidence/collaboration_chain.json）；这是对真实消息的索引/选段，缺失历史明确标注，原始档案单独保管。详细范围见验证摘要（文件：validation/review_summary.json）。陌生人类团队使用、提示词多轮稳定性、通用PYNQ跨板实测未评估。

# 工作流与使用方法

以下提示词是本次从经验整理的模板，不是历史聊天原文。参数由 Codex 优先从当前工程、配置及可访问记录中查找并核对，例子不代表所有模型都采用 INT8 或同一门槛。

各节的“执行所需材料”是工作流的依赖清单，不是要求用户手动提交的清单。Codex 应先自动查找材料、核对身份与完整性，再执行已授权的检查。只有经过查找仍无法获取材料、无法消除关键歧义，或需要用户完成实体操作及补充必要授权时，才提出具体问题。缺失的实测证据不得编造，计划和参考结果不得替代实测。

## 一：模型与平台身份

适用：换板、换输入尺寸、单域替换多域模型、上位机与板端版本不一致。

执行所需材料（由 Codex 优先自动查找）：最新需求、数据类别表、输入/预处理定义、权重与包、ELF、bitstream/XSA、运行记录。

流程：
1. 建立“目标配置、离线候选、已运行配置”三列，分别标记证据时间。
2. 校验类别顺序、编号、分辨率、协议与预处理；确认包身份和源权重身份的不同含义。
3. 将 ELF 与对应 XSA、BSP、寄存器/DMA 契约绑定；按实际对象计算 SHA-256。
4. 对未知项标为未确认，避免拿旧板资源或旧分辨率性能替代新板结论。

提示词：

> 根据最新用户决定与这些产物，建立目标/候选/已运行身份表。逐项核对权重、类别、输入、预处理、模型包、ELF、XSA/bitstream、工具版本与证据时间。发现冲突时引用具体来源；先做只读核查，不操作板卡。

输出：身份表、冲突项和下一项最小检查。退出条件：无法确定输入、类别或固件/硬件契约时，不宣称兼容或建议直接加载。

历史经验和本次核验范围见经验说明（文件：lessons.md）与验证摘要（文件：../validation/review_summary.json）。
